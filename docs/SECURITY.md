# Security

Threat model → controls → where it's enforced and how it's tested.

| Threat | Controls | Enforced in | Tested |
|---|---|---|---|
| **Token theft** | The token lives only in the OS credential store (`keyring`, service `ReelEngine`): Windows Credential Manager, or the macOS Keychain since v1.2. Never in files, config, the DB, OneDrive, logs or command lines. `set-secret.ps1` and `reel connect` use hidden input and pass secrets via stdin. The Authorization header is used where the API allows (the refresh endpoint needs the query parameter by design). Every log line, stored error and raw API payload is redacted: token shapes, `access_token=`, Bearer/OAuth headers, JSON token fields and registered secret values; `paging` URLs are dropped. | `secrets.py`, `log.py`, `graph.py`, `cli.py` | `tests/test_config_log.py` (redaction), `tests/test_publisher.py` (no token in any DB column or raw payload) |
| **Account takeover** | Checklist for Yazeed: authenticator-app 2FA on Instagram and Meta, recovery codes kept offline, a unique password in a password manager, login alerts, a monthly review of connected apps, and a weekly Account Status check (SETUP.md). The app stays in Development mode with least-privilege scopes (no comments scope). | `docs/SETUP.md` | manual |
| **Accidental harmful or false post** | Dry-run by default. Live needs a LIVE-OK line in DECISIONS.md, a token, a passing `doctor --live` and a typed confirmation. Kill switch: `reel pause` / `data/PAUSE`, checked before every publish and again before `media_publish`. Cap of 1 post per day (hard max 3) and a 6 h gap. Facts gate (known-trap rules from `facts.yaml`) + legal gate (bait, guarantees, salaries, third-party ads, service CTA) + an independent critique (score ≥ 7) + technical QA; any failure means the reel is held, never posted. The learner can't change the gates or the hard limits. | `config.py` (HARD_*), `gates.py`, `qa.py`, `jobs.py`, `publisher.py`, `learner.apply_review` | `tests/test_gates_example.py` (+ the owner's private `test_gates.py`), `tests/test_learner.py`, `tests/test_publisher.py`, `tests/test_cli.py` |
| **Double posting / crash** | Every state change is persisted before its side effect; the container id is saved before upload and `publish_requested_at` before publish. On restart the container status is read back and the post found in `/me/media`. | `publisher.py`, `pipeline.py`, `db.py` | crash-at-every-step tests in `tests/test_publisher.py`, `tests/test_state.py` |
| **Prompt injection** (via transcripts, trend pages, other accounts' captions) | Writing tasks run the Claude CLI with **no tools** and `--safe-mode` in an empty sandbox. Only the trends task gets the read-only WebSearch/WebFetch; any other tool is refused in code. Prompts mark untrusted input as data. Outputs are schema-validated, then re-checked by the deterministic gates, so a manipulated output still can't pass the facts/legal gates. | `brain.py`, `prompts/*.md` | `tests/test_brain_vault.py` |
| **Supply chain** | Pinned `requirements.txt`; `pip-audit` (0 known vulnerabilities, see `docs/qa/security/pip-audit.txt`); `bandit` (0 issues after review; every `# nosec` states why); the ffmpeg archive sha256 is pinned and cross-checked on two hosts; fonts are verified against the GitHub blob hash; the Whisper model revision is pinned. No trojan-source bidi characters in the code (they are written as escapes). | `requirements.txt`, `scripts/bootstrap_assets.py` | `docs/qa/security/` |
| **Dashboard exposure** | Binds to 127.0.0.1 only (non-loopback hosts refused); GET/HEAD only, except POST to `/api/*` when the write API is on (row below); strict CSP (no inline script or style; `script-src 'self'`; `connect-src 'self'` so the page's own `app.js` can reach the local API; no external requests; `form-action 'none'`); nosniff, no-referrer, frame deny; path-traversal-safe media routes; a Host-header check against DNS rebinding; no secrets rendered; source links shown as text, never as external links. | `dashboard/server.py`, `dashboard/build.py` | `tests/test_dashboard.py` |
| **Dashboard writes: CSRF / cross-site upload** (added 2026-10-14) | On only with `[dashboard] allow_writes = true` (`--read-only` turns it off; the demo DB never accepts uploads). Every POST needs an `Origin` equal to this loopback origin, `Sec-Fetch-Site` same-origin when sent, and `X-CSRF-Token` = a random per-process token (`secrets.token_urlsafe(32)`, compared in constant time) that only a same-origin page can read from `GET /api/session` (no CORS headers; the custom header forces a preflight, and OPTIONS is 405). `Content-Length` required, no chunked bodies; JSON bodies ≤ 256 KB. | `dashboard/api.py`, `dashboard/server.py` | `tests/test_dashboard_api.py` |
| **Malicious or broken upload** | Video allowlist (`video/mp4`, `video/quicktime`, `video/x-m4v` with a matching `.mp4/.mov/.m4v` extension) plus an MP4/QuickTime signature check on the first bytes; size cap `[upload] max_mb` (default 2048) checked before reading; refuses when free disk would drop under `[upload] min_free_gb`; filename reduced to an ASCII basename (no path, no leading dot, 64 chars); one upload at a time; 60 s socket timeout. Streamed to a dot-prefixed temp file in the inbox (intake ignores dot files), fsync'd, sha256 computed on the way, then `os.replace` into place; any failure deletes the temp file. A sha256 already known is reported as a duplicate and not kept. From there the normal intake path runs (stability ticks, dedupe, move to `data/raw`, every QA gate): **uploading never schedules or publishes, and dry-run stays the default**. | `dashboard/api.py`, `intake.py` | `tests/test_dashboard_api.py` |
| **Other accounts' data (PDPL, Meta terms)** (added 2026-10-14) | Official API only: Business Discovery behind an adapter that refuses unless `[accounts] discovery = "facebook_login"` (it doesn't exist on the Instagram-Login path), its own keyring token `fb_discovery_token`, minimal fields only, never on a schedule. Otherwise manual import: pasted permalinks are stored as text and never fetched. Never stored: profile pictures, bios, locations, comments/commenters, follower lists. Captions wiped after `retention_days` (90) and rows deleted after `metrics_retention_days` (180), both counted from the first import; `reel accounts forget` / Remove deletes at once (secure_delete + VACUUM; the dashboard also checkpoints the WAL). Pseudonyms are never reused. Before any brain call, usernames → `ACC_nn`, other @mentions → `@user`, URLs dropped; the mapping never leaves the PC. A copy guard holds any reel, brief script or idea that shares ≥ 60% of its 5-word phrases with a stored reference/competitor caption. See `docs/PRIVACY.md`. | `accounts.py`, `qa.py`, `brief.py` | `tests/test_accounts.py` |
| **Occasion content (flag, Shahada, emblem, leaders, religion)** (added 2026-10-14; Pride rule and per-day checklists 2026-10-15) | Additive legal rules in `brand/gates_occasions.yaml` (hold or warn), checked with every other content gate; the learner can't change them and nothing in `gates.yaml` was loosened. The filming brief carries a checklist for what text matching can't see (flag on the floor, altered flag, emblem in frame). | `gates.py`, `brief.py` | `tests/test_occasion_gates.py` |
| **Telegram notifications** (added 2026-10-15) | Off by default and unconfigured. The bot token lives only in the Keychain / Credential Manager (`telegram_bot_token`; `reel notify setup-telegram` uses hidden input or stdin). Messages go only to the `telegram_chat_ids` allow-list; chat ids are never logged or stored in notification rows. Only a fixed set of kinds (`occasion`, `action`, `error`; `published`, `brief` opt-in); non-occasion kinds send the title only. A message is refused if it contains an @handle, a URL, a home-folder path or anything the redactor masks. `protect_content` and link previews off. The request URL holds the token, so it is never logged: request errors are reduced to the exception class name, and Telegram's error text has URLs and long digit runs removed. Incoming messages are ignored (no bot commands). The test suite refuses any call to api.telegram.org (`tests/conftest.py`). | `notify.py`, `cli.py` | `tests/test_notify.py`, `tests/conftest.py` |
| **macOS desktop notifications and launchd** (added 2026-10-15) | `osascript` gets a fixed AppleScript on stdin and the title/body as argv (never interpolated into the script, no shell). launchd plists are built with `plistlib`, hold no secrets, use absolute paths and a fixed minimal PATH; `launchctl` is called with list args through an injectable runner. `install`/`uninstall` need a person to type `INSTALL`/`UNINSTALL` in a terminal (no flag skips it, and they refuse without a terminal); they were not run. | `notify.py`, `macsched.py` | `tests/test_mac.py`, `tests/test_macsched.py` |
| **macOS ffmpeg supply chain** (added 2026-10-15) | `scripts/setup-mac.sh` downloads the Martin Riedl arm64 release 9.0.2 from pinned URLs and checks pinned sha256 values (`shasum -a 256 -c`) before unpacking; a mismatch stops the script. The vendor publishes the checksum on the same host as the file (no second host as for Windows D-002), so the build's Apple code signature (Team ID KU3N25YGLU) is printed as a second signal. The quarantine attribute is removed only from those two files. Build flags and FriBidi are verified after install. | `scripts/setup-mac.sh`, `doctor.py` | manual (run 2026-10-15) |
| **New brain tasks** (added 2026-10-15) | `occasion_ideas` and `recommend` run like every writing task: no tools, `--safe-mode`, schema-validated, plus a validator that rejects content-gate hard hits, copied captions (copy guard), @handles, links and unknown occasion ids. Both count in the daily cap; reminder ideas leave `[calendar] brain_reserve_calls` (10) free so reel processing is never starved, and use at most one call per run. The suite blocks real Claude CLI calls unless a test is marked `brain` (`tests/conftest.py`). | `ideas.py`, `accounts.py`, `brain.py` | `tests/test_reminders.py`, `tests/test_recommend.py` |
| **Link-account API** (added 2026-10-15) | The `link` / `recommend_status` actions sit behind the same Origin + CSRF + Content-Length checks as every POST. One background job per process (a second account while one runs → 409), its own DB connection, never the engine lock; the site is rebuilt before the job reports done. Demo mode never calls the brain. | `dashboard/api.py` | `tests/test_dashboard_api.py` |
| **Data loss** | Daily SQLite online backup (7 kept, checked with `quick_check`) plus a copy in OneDrive (the DB holds no secrets). Raw clips are moved out of OneDrive into `data/raw/` and kept; duplicates are moved, never deleted. | `jobs.py`, `intake.py` | `tests/test_intake.py` |
| **Vault damage** | The engine writes only inside `12 Social Media/`, only between its own markers, never in `10 Source Archive/`; traversal is refused. Preview folder until Yazeed enables it. | `vault.py` | `tests/test_brain_vault.py` |
| **Subscription abuse** | Brain call cap: 60 per 24 h. The API key is stripped from the child environment (no surprise API bill). | `brain.py` | `tests/test_brain_vault.py` |

**Legal note:** no paid promotion or third-party ads (Saudi Mawthooq rules): hard gate. The service CTA stays off until the offer page is live and the legal checklist (Freelance Document, e-commerce authentication on منصة الأعمال (business.sa), PDPL consent) is done. Only Yazeed can switch it on (`cta.service_enabled`).

**If a token leaks:** Meta app dashboard → regenerate the token (this invalidates the old one) → `reel connect` → `reel doctor --live`.
